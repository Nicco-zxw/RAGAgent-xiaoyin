# 05 复盘与下一步

本文为AI根据开发过程整理的工程复盘，不冒充提交者个人学习心得。

最难问题是区分“引用原文存在”与“原文足以支持结论”，以及冲突条款、适用范围与替代关系的区别。只按版本日期选新规定会产生无依据答案；不同部门期限也不必然矛盾。

实际教训：
- 字符匹配与Mock通过不足以证明真实决策效果。真实运行发现了格式、字段、问法歧义和过度确定问题。
- “报销期限30天”不能自动补成“自费用发生起30天内提交材料”。应补明确合成条款并保留资料缺失用例，而非改提示强迫作答。
- 独立模型审查改善了本批必要条件结果，但增加用量及延迟，仍可能与生成模型共同犯错。
- HTTP 402不能记作业务失败或通过；日志、时间和未执行状态应可追溯。
- 尽早采用统一证据目录和开发计时，可减少交付整理成本。本项目全过程计时存在无法补回的缺口。

提交者应自行补充：最难理解的代码、亲自做过的修改、独立验证结果和个人学习收获。

下一步优先完成个人复核、干净环境复验和GitHub提交；生产权限、文档同步、向量检索等仅在实际需求和失败数据支持时考虑，不为框架名称扩展范围。

独立复核任务已分配，见[personal-review-tasks.md](personal-review-tasks.md)。个人心得应在本人实际完成后填写，当前不编造学习成果。
