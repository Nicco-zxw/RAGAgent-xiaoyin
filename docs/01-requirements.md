# 01 需求与成功标准

用户为需要查询制度或产品信息的员工。目标是提供可追溯答案，遇到冲突或缺少资料时明确表达不确定性。

输入为问题、可选对话历史及带文档ID、版本日期的合成制度；输出为answer、citations、gaps、conflicts、follow_up_question、status。引用必须包含文档ID、版本、片段ID和原文。

范围：Python CLI、本地JSON资料、检索与片段读取、真实模型动作循环、引用校验、证据审查、预算及日志。保留明确标识的离线Mock。无需界面、部署、多Agent或生产Runtime。

成功标准：
- 模型真实选择动作并根据工具观察继续或停止，至少两条不同路径可审查。
- 六类必验：明确答案、文档冲突、资料外问题、相似改写、上下文追问、工具失败。
- D01为30天、D02为15天且无适用依据时补查并追问，不能任意选15天；只有D01时可据此回答。
- 修改期限或新增替代依据时，答案与动作响应变化。
- 达到预算返回未完成状态；引用来自实际已读原文。
- 代码、运行步骤、实际证据、限制与贡献说明同仓库交付。

验收映射与实际结果见[03-evaluation.md](03-evaluation.md)。合成制度不是企业真实政策。真实文档解析、权限管理和大规模索引不在本次范围。
